9월 1일에 Claude Fable 5.1이 나왔다. 벤치마크는 잠깐 접어두자.
릴리스 노트에서 실제로 남의 코드를 부수는 줄은 세 개고, 그중 둘은
[지난번에 쓴 프롬프트 캐시 이야기](/blog/2026-08-31-oauth-토큰이-갱신될-때마다-프롬프트-캐시가-통째로-날아갔다/)의
정확한 후속편이다.

지난 글의 결론은 **캐시가 보는 건 내용이 아니라 직렬화된 바이트**라는 것이었다.
그때는 그걸 어기면 요금이 조금 더 나왔다. Fable 5.1에서는 400이 떨어진다.

## 대화 기록은 이제 append-only다

가장 큰 변경부터. Fable 5.1에서 **지난 턴을 고치면 그 뒤의 thinking 블록이 전부 무효**가 된다.
다음 요청은 이렇게 죽는다.

```text
The block is bound to a different conversation
```

"고친다"의 범위가 넓다.

- top-level `system` 프롬프트를 바꿨다
- `tools` 배열을 다시 만들었다 (순서가 달라져도)
- 과거 메시지 하나를 수정·삭제·재정렬했다

세 번째만 대화 편집처럼 보이지만 셋 다 같은 취급이다. 접두사가 어긋나는 건 매한가지니까.
직접 `messages` 배열을 조립하는 코드가 흔히 하는 짓들이 여기에 걸린다 —
매 요청 과거 턴에 상태 줄을 주입했다가 다음 요청에 빼거나, 도구 목록을 요청마다
새로 빌드하거나, 오래된 턴을 잘라내 컨텍스트를 줄이거나.

허용되는 건 접두사를 앞에서부터 그대로 두는 연산뿐이다.

| 해도 되는 것 | 하면 죽는 것 |
| --- | --- |
| 맨 앞부터 순서대로 thinking 블록 걷어내기 | 중간 턴 수정·삭제 |
| 서버측 compaction / context editing | `system`·`tools` 재구성 |
| `cache_control` 마커 옮기기 | 턴 재정렬 |
| `effort` 바꾸기 | 히스토리 재작성 후 재전송 |

계정 생성일이 **2026-08-31 이후**면 강제 적용이고, 그 전 계정은
`prefix_mismatch_behavior`를 명시했을 때만 걸린다. Claude Code·claude.ai·Agent SDK를
쓰고 있으면 이미 알아서 접두사를 지켜주므로 아무 일도 안 일어난다.
직접 API를 부르는 쪽만 확인하면 된다.

## 강제 tool use가 사라졌다

`tool_choice`에 `{"type": "any"}`나 `{"type": "tool", "name": ...}`을 주면 400이다.
토큰 카운팅 엔드포인트에서도 똑같이 거부한다. `auto`와 `none`은 그대로다.

이유가 납득이 간다. Fable 5.1은 thinking이 **항상 켜져 있는데**, 툴 호출을 강제하면
그 추론을 건너뛰고 곧장 인자를 만들게 된다. 생각할 자리를 뺏으면 생각이 툴 인자 안으로
밀려 들어간다. 그래서 아예 막았다.

대체 수단은 셋 중 하나다.

- `auto` + `strict: true` — 스키마 검증은 그대로 받으면서 호출 여부는 모델에 맡긴다
- structured outputs — "무조건 이 모양으로 답해라"가 목적이었다면 이쪽이 정답이다
- 프롬프트에 명시 — "X를 물어보면 반드시 Y 툴을 써라". 생각보다 잘 따른다

## thinking 블록에 모델 이름이 박혔다

Fable 5.1이 만든 thinking 블록은 **이전 모델이 못 읽는다**. 반대 방향(이전 모델의 블록을
5.1이 읽는 것)은 된다. 한 방향 호환이다.

폴백이나 라우터로 모델을 갈아타는 구성에서 조용히 새는 지점이다. 읽지 못하는 블록은
그냥 드롭되고 — 과금은 안 되고 `input_tokens`에도 안 잡힌다 — **아무 경고도 없다.**
드롭을 보고 싶으면 베타 헤더를 붙여야 한다.

```text
anthropic-beta: thinking-binding-controls-2026-08-01
```

그러면 응답의 `input_transformations`에 `reason: "prefix_binding_mismatch"`로 뭐가 빠졌는지 나온다.
모델을 섞어 쓰는 파이프라인이라면 켜두는 게 맞다.

## 캐시 읽기가 4분의 1이 됐다

가격표에서 눈에 띄는 건 하나뿐이다.

| | Fable 5 | Fable 5.1 |
| --- | ---: | ---: |
| 입력 | $10 / MTok | $10 / MTok |
| 출력 | $50 / MTok | $50 / MTok |
| 5분 캐시 쓰기 | $12.50 | $12.50 |
| **캐시 읽기** | **$1.00** | **$0.25** |

입출력은 그대로고 캐시 읽기만 75% 내렸다. 이게 왜 특이하냐면,
**다른 모든 Claude 모델에서 캐시 읽기는 기본 입력가의 0.1배**인데
Fable 5.1만 **0.025배**이기 때문이다.

비용 계산기에 "캐시 읽기 = 입력가 × 0.1"을 상수로 박아둔 코드가 있다면 지금 틀렸다.
내 관측 도구도 같은 가정을 하고 있어서 고쳐야 한다. 모델별 단가표를 따로 두는 것 말고는
방법이 없다.

가격이 이렇게 붙은 게 우연은 아니다. 접두사를 안 건드리고 계속 재사용하는 워크로드
— 그러니까 위의 append-only 규칙을 지키는 워크로드 — 에 보상이 몰려 있다.
Anthropic은 일반 작업 25%, 에이전트 작업 45%까지 총비용이 준다고 말한다.

## 대신 준 것

제약을 걸었으니 우회로도 같이 나왔다. 셋 다 베타 헤더가 필요하다.

**턴 중간에 effort 바꾸기** (`mid-conversation-output-config-2026-07-01`).
어려운 단계만 effort를 올리고 나머지는 내린다. 캐시는 안 깨진다.
Fable 5.1뿐 아니라 **Opus 5에서도 된다** — 이게 실용적으로는 제일 크다.

```json
{ "role": "system", "content": [], "output_config": { "effort": "low" } }
```

**턴 스코프 시스템 메시지** (`mid-conversation-system-clear-at-2026-08-21`).
`clear_at: "next_user_message"`를 붙이면 그 턴에만 시스템 권한으로 먹고 다음 턴부터는
모델에게 안 보인다. **메시지는 배열에 그대로 남겨서 보낸다** — 그래서 히스토리가 안 바뀌고,
캐시도 thinking 바인딩도 살아 있다. 지운 메시지는 입력 토큰으로 세지도 않는다.

```json
{
  "role": "system",
  "clear_at": "next_user_message",
  "content": "결과가 받은편지함에 들어왔다. 코드를 더 돌리기 전에 확인할 것."
}
```

앞에서 말한 "과거 턴에 상태 줄을 주입했다 빼는" 패턴의 정식 해법이 이거다.
하던 대로 하면 400이고, 이걸 쓰면 된다.

**`thinking.display: "updates"`** (`thinking-display-updates-2026-08-18`).
추론 자체는 계속 숨기고 툴 호출 사이의 진행 상황 텍스트만 흘려준다.
긴 에이전트 턴이 사용자에게 침묵으로 보이던 문제가 이걸로 풀린다.

## 프롬프트를 손봐야 하는 것들

모델을 바꾸면 코드는 안 고쳐도 행동이 달라지는 것들이 있다. 릴리스 노트가 이걸 꽤
정직하게 적어놨다.

- **병렬 툴 호출이 줄었다.** Fable 5가 한 턴에 묶어 부르던 자리에서 하나씩 부를 수 있다.
  답은 같은데 왕복과 시간이 는다. "가능하면 한 턴에 모아서 부르라"는 줄을 넣어야 한다.
- **`low` effort에서 검색을 덜 한다.** 기억으로 답하려 든다. 최신 정보가 필요한 턴은
  effort를 올린다(위의 턴 중간 변경).
- **작은 수정에도 파일 전체를 다시 쓴다.** 결과는 맞는데 출력 토큰이 는다. 타겟 편집을 명시할 것.
- **진행 업데이트가 줄었다** — 특히 높은 effort에서. `display: "updates"`로 메운다.
- **채팅에서 볼드·헤더를 덜 쓴다.** 옛 모델용으로 써둔 "포맷 쓰지 마라" 규칙이 남아 있으면
  이제는 구조를 죽인다. 빼는 게 낫다.

## 그래서 갈아탈 것인가

벤치마크는 Fable 5.1이 Opus 5를 전부 앞선다. Terminal-Bench 4.0이 55.8% 대 52.3%,
Terminal-Bench-Science는 52.6%로 Fable 5(24.7%)의 두 배가 넘는다.

그런데 문서가 스스로 권하는 건 이거다.

> 대부분의 워크로드는 Claude Opus 5로 시작하라. 높은 effort로 돌린 Opus 5가
> 그래도 eval을 통과하지 못할 때 Fable 5.1을 쓰라.

가격이 정확히 두 배($10/$50 대 $5/$25)이기 때문이다. 캐시 읽기 $0.25가 그 격차를
좁혀주긴 하는데, 그건 **접두사를 길게 재사용하는 세션에서만** 그렇다.
짧은 단발 호출을 많이 던지는 구성이면 캐시 할인이 닿지 않는다.

## 남는 것

Fable 5.1의 변경 셋 중 둘이 접두사 이야기다. 강제 tool use 제거는 "생각할 자리를
뺏지 마라"고, thinking 바인딩 둘은 "만들어진 맥락을 나중에 위조하지 마라"다.

지난 글에서 캐시가 접두사를 본다는 걸 요금으로 배웠다면, 이번엔 API가 그걸
검증하기 시작했다. **대화 기록을 append-only 원장으로 다루라**는 요구가
성능 최적화에서 계약으로 승격된 셈이다.

마침 이 블로그의 좌표 원장도 append-only다. 한 번 박힌 건 다시 계산하지 않는다.
비슷한 이유에서다 — 뒤늦게 고친 과거는 앞에서 쌓아올린 것을 전부 무너뜨린다.
