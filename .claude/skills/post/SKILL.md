# 쓰기 화면으로

`/write`는 브라우저에서 글 한 편을 짓는 화면이다. frontmatter·본문·미리보기·슬러그·
읽는 시간·지문을 한 자리에서 보여주고, 다 쓰면 마크다운을 내려받기·클립보드·GitHub
새 파일 화면으로 내보낸다.

**이 명령이 하는 일은 거기로 데려다 놓는 것뿐이다.** 화면을 열고, 주소를 알려주고, 끝낸다.

## 어디를 여나

1. **dev 서버가 떠 있으면 그쪽.** 아직 발행하지 않은 글까지 편집기 목록에 뜬다

   ```bash
   npx astro dev status
   ```

   떠 있으면 그 포트의 `/write/`가 답이다 (기본 4321, 쓰이고 있으면 4322…).

2. **안 떠 있으면 배포된 쪽.** <https://ollybaysion.github.io/write/> — 서버가 필요 없고
   폰에서도 열린다. 대개 이쪽이면 충분하다.

브라우저는 `xdg-open <주소>`로 연다. 창이 안 뜨는 환경이면 주소만 알려주고 끝낸다 —
사용자가 직접 누르면 된다.

## dev를 띄워야 한다면

아직 발행하지 않은 글을 편집기 목록에서 꺼내려면 로컬이 필요하다. 그런데
**`npm run dev`는 좌표를 박는다**(`predev`가 `embed → coords → derived`를 돌린다).
띄우기 전에 반드시 확인한다:

```bash
npm run embed:check
```

빠진 벡터가 있다며 죽으면 **아직 벡터가 없는 글이 콘텐츠 폴더에 있다는 뜻이다.**
여기서 dev를 띄우면 그 글은 **지금 상태 그대로** 좌표가 박히고 다시 계산되지 않는다.
초안이면 그 초안이 그 글의 자리가 된다.

그런 글이 있으면 **멈추고 사용자에게 알린다.** 그 글이 완성됐는지 먼저 묻는다.
깨끗할 때만 띄운다:

```bash
npm run dev -- --background
npx astro dev status
```

내릴 때는 `npx astro dev stop`.

## 화면에서 나온 뒤

편집기는 파일을 못 쓴다. 마크다운을 받아왔으면 그다음은 **write-post 스킬의 순서**다 —
파일로 앉히고, 카테고리·태그·본문이 다 정해진 걸 확인하고, 좌표를 박고, 원장 두 개
(`coordinates.json` · `vectors.json`)를 글과 함께 커밋해 PR을 낸다.

GitHub 새 파일 화면으로 바로 커밋했다면 **벡터가 아직 없다.** 로컬에서 파이프라인을
한 번 돌려 원장을 채우고 그 변경분을 올려야 배포가 산다 — 안 그러면 `embed:check`가
배포를 세운다.
