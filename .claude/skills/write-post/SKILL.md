# 새 글

**순서가 곧 규칙이다.** 좌표는 첫 `npm run dev`·`npm run build` 때 박히고 **다시 계산되지
않는다**(원장 append-only). 그래서 카테고리·태그·본문이 그 전에 정해져 있어야 한다.
순서를 어기면 되돌릴 방법이 없다 — 슬러그를 바꿔 새 글로 다시 내는 수밖에 없다.

```text
카테고리·태그 정하기 → 초안 → 글 완성 → dev 실행(좌표·벡터 박힘) → 커밋(원장 포함) → PR
```

## 0. 먼저 물을 것

사용자가 "글 쓰자"까지만 말했다면 **무엇을 쓸지부터 듣는다.** 제목·카테고리·태그가
정해지기 전에 `npm run new`를 부르지 않는다. 필요한 건 넷이다:

- **제목** — 파일 이름과 슬러그가 여기서 나온다
- **카테고리** — 각도(화면에서의 자리)가 여기서 나온다. 하나만 고른다
- **태그** — 몇 개든. 없어도 된다(유사도는 이제 글 전체 임베딩이 잰다)
- 시리즈면 **시리즈 이름** (연재의 다음 화인지)

## 1. 카테고리 — 자리를 정하는 일이다

등록된 카테고리와 호:

| 카테고리 | 호 | 중심 | 빛구멍에서 보아 |
| --- | --- | --- | --- |
| 커피 | 210°~330° | 270° | 위 |
| 개발 | 30°~150° | 90° | 아래 |
| 영화 | 150°~210° | 180° | 왼쪽 |
| 여행 | 330°~30° | 0° | 오른쪽 |

각도는 화면 좌표계다(x = cos, y = sin, y는 아래로 자란다). 호 안에서의 정확한 각도는
같은 호의 다른 글들과의 유사도가 정하고, 슬러그 해시가 ±1° 흔든다 — 같은 자리에 두
글이 겹치지 않게.

없는 카테고리를 쓰려면 **먼저** `src/config/categories.json`에 호와 색을 등록한다.
빈 호가 남아 있는지, 이웃 호를 밀지 않는지 보고 정한다. 등록 없이 쓰면 빌드가 죽는다.

## 2. 초안

```bash
npm run new "예가체페를 처음 만난 날"
npm run new "탬핑을 다시 배웠다" -- -c 커피 -t 에스프레소,탬핑
npm run new "V60 레시피 정착기" -- -s "예가체페 연대기" --episode 3
```

`src/content/blog/{날짜-제목}.md`를 만든다. **npm이 `-`로 시작하는 인자를 먹으므로
옵션 앞에는 `--`를 둔다.**

| 옵션 | |
| --- | --- |
| `-c, --category` | 기본 커피 |
| `-t, --tags` | 쉼표로 나눔 |
| `-s, --series` | 연재 이름 |
| `--episode` | 생략하면 시리즈 안에서 날짜순 |
| `--date` | 기본 오늘 |
| `-d, --description` | 목록·글 화면의 한 줄 소개 |

이 명령은 **좌표를 매기지 않는다.** frontmatter 한 장과 빈 본문만 놓는다.

## 3. 글을 끝까지 쓴다

여기가 되돌릴 수 없는 지점 직전이다. 유사도 v2는 **글 전체 임베딩**의 코사인이라,
초안 상태로 dev를 띄우면 그 초안이 그 글의 좌표가 된다. 나중에 본문을 채워도
벡터는 다시 뜨지 않는다(경고만 뜬다).

- 제목·소개·태그·본문이 다 있는가
- 카테고리를 바꿀 생각이 조금이라도 있는가 → 지금 바꾼다

## 4. 좌표를 박는다

```bash
npm run dev -- --background
```

`predev`가 `embed → coords → derived`를 차례로 돌린다. **`astro dev`를 직접 부르면
이 파이프라인을 건너뛰어** 새 글의 좌표와 파생 데이터가 없는 채로 뜬다.

```bash
npx astro dev status   # 떠 있나
npx astro dev logs     # 무슨 일이 있었나
npx astro dev stop     # 내린다 — 반드시 내린다
```

첫 실행이면 임베딩 모델(수백 MB)을 내려받는다. 모델이 없다는 에러가 나면 `npm i`.

화면에서 확인할 것:

- 새 글의 점이 제 호 안에 있는가
- 꼬리의 "가까운 글" 목록이 말이 되는가 — **가까우면 닮았다**가 이 블로그의 계약이다
- 다른 카테고리인데 닮은 글이 있으면 "다른 자리에서 닮은 글"에 뜬다

## 5. 커밋 — 원장 두 개를 같이 넣는다

```bash
git switch -c post/{슬러그}
git add src/content/blog/{파일}.md src/data/coordinates.json src/data/vectors.json
```

`src/data/generated/`는 커밋하지 않는다(빌드가 만든다). **`main`에 직접 push하지
않는다** — 브랜치를 파고 PR을 낸다. 머지는 사람이 한다.

```bash
npm test          # 좌표 엔진 · 원장 · "가까우면 닮았다" 계약
npm run build     # CI가 도는 길과 같다
```

## 함정

**슬러그를 바꾸면 새 글이다.** 제목이나 날짜를 고치면 파일 이름이 바뀌고, 옛 좌표는
원장에 남은 채 경고만 뜬다. 좌표를 다시 받고 싶을 때 쓸 수 있는 유일한 손잡이이기도
하다 — 아직 안 낸 글이면 원장에서 그 줄을 지우는 편이 낫다.

**글을 고쳐도 벡터는 다시 안 뜬다.** 지문이 어긋나면 경고만 뜨고 넘어간다. 크게
고쳤다면 그 글의 좌표는 옛 글의 것이다. 감수할지 슬러그를 새로 받을지 판단한다.

**태그는 NFC + trim + lowercase로 정규화된다.** "커피 "와 "커피"는 같은 태그다.

**CI는 모델 없이 돈다.** 벡터가 커밋되어 오기 때문이다. 그래서 원장을 빠뜨리고 PR을
내면 CI가 "빠진 벡터가 있다"며 죽는다 — 그게 안전장치다.
